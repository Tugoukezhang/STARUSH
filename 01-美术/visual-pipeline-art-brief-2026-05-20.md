# ST☆RUSH 视觉方案 — 美术组对接

> 原型组 | 2026-05-20
> 风格方向：崩坏星穹铁道 · 2D 弹幕射击适配

---

## 一、结论

**不追求 3D 实时光照**（2D sprite 物理上做不到动态 PBR）。
**追求 2D 弹幕射击品类顶配**——四层特效叠加。

---

## 二、四层渲染方案

| 层级 | 内容 | 技术手段 | 谁做 |
|------|------|---------|------|
| **L1 角色本体** | sprite PNG，4方向×10帧，自带微高光（模拟舞台顶灯） | Phaser `load.spritesheet()` | 美术出图 |
| **L2 舞台灯光** | 聚光灯粒子从顶往下打，覆盖全场 | Phaser `ParticleEmitter` — 代码直接配 | 原型 |
| **L3 命中反馈** | 角色受击/攻击瞬间白闪 tint（0.1s） | `sprite.setTint(0xFFFFFF)` — 一行代码 | 原型 |
| **L4 弹幕特效** | 弹幕拖尾粒子 + 氛围粒子 Additive 混合 | Phaser 粒子系统原生支持 | 原型 |

L2-L4 零美术工作量，纯引擎侧。

---

## 三、美术需要交付

| 需求 | 规格 |
|------|------|
| 角色 | **仅 绯樱**（🎤 甜蜜主唱形态） |
| 动作 | 待机 4 帧 / 移动 4 帧 / 射击 2 帧 |
| 方向 | 4 方向（下 / 左下 / 左 / 左上……TBD 确认） |
| 格式 | 单张 PNG spritesheet + JSON atlas |
| 尺寸 | ≤2048×2048 单张 |
| 风格 | 星铁风平涂 + 2-3px 线 + 干净光影，自带微弱顶部高光 |
| 光影 | **预烘焙进帧**——不需要单独的 lightmap 通道 |

---

## 四、性能预估

| 指标 | 数值 |
|------|------|
| 单帧大小 | 150-200KB |
| 绯樱 40 帧总量 | ≈1.5-2MB |
| 5 角色全上 | ≈35MB 纹理内存 |
| 微信小游戏上限 | ≈200MB |
| 结论 | ✅ 充足 |

---

## 五、不需要的

- ❌ 实时 rim light / 动态光源
- ❌ 多通道光照贴图（lightmap / normal map）
- ❌ 3D 模型或骨骼动画
- ❌ Spine / Live2D（Phase 1 不接入）
