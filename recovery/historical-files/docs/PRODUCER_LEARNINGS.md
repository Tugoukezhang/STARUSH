# Producer Learnings

日期：2026-05-24

## 协作流程问题记录

### 1. 专项任务不能漏发

问题：

- 制作人曾只单独列出策划专项任务，没有同步列出程序专项和美术专项，导致用户复制分发困难。

改进规则：

- 以后只要出现“需要分发给专项对话”的任务，必须按专项分别列出完整可复制文本。
- 至少检查是否覆盖：策划、程序、美术。
- 如果某个专项本轮没有任务，也要明确写“本轮无新任务”。
- 任务块必须使用清晰标题，例如：

```text
【发给策划专项】
...
```

```text
【发给程序专项】
...
```

```text
【发给美术专项】
...
```

### 2. 专项反馈必须回到制作人主控

问题：

- 多对话协作容易让信息分散，专项报告如果不回流，制作人无法统一决策。

改进规则：

- 用户后续应把策划、美术、程序专项反馈都发回制作人主控对话。
- 制作人负责归档、提炼冲突、排序优先级、输出统一下一步。
- 不根据单一专项反馈直接开工，除非是明确 P0 崩溃或用户明确授权。

### 3. 反馈格式建议

用户可按以下格式贴回：

```text
【策划反馈 vN】
...
```

```text
【程序反馈 vN】
...
```

```text
【美术反馈 vN】
...
```

如果反馈很长，可以分多条发送，但必须标明来源专项。

### 4. 程序专项结论要落文档

问题：

- 用户需要把程序专项的审查、风险评估、执行方案转发给制作人；只在对话里输出会增加复制和归档成本。

改进规则：

- 以后程序专项输出接手审查、执行方案、风险评估或验收方案时，必须同步整理成 `docs/` 下的制作人可读 Markdown 文档。
- 文档要包含：当前状态、涉及文件、最小修法、风险点、验证步骤、可合并开发项、必须单独验收项。
- 最终回复必须告知文档路径。

## 制作人主控承诺

- 收到专项反馈后，先复述关键结论，再做制作人裁决。
- 对冲突意见明确指出：谁的意见优先、为什么。
- 需要分发的新任务，单独给出完整可复制文本。
- 需要写入项目文档时，优先更新 `docs/CURRENT_SPECIALIST_HANDOFFS.md`、`STARUSH_PHASE1_ROADMAP.md` 或本文件。

### 4. 专项结论默认整理成文档

问题：

- 用户需要把专项结论转发给制作人主控，单纯聊天输出不利于归档、复盘和后续拍板。

改进规则：

- 以后专项输出只要形成阶段性结论、规格、路线图、交接或验收口径，默认同步整理成 Markdown 文档。
- 文档优先放在 `docs/`；如果是纯美术资产规格或素材归档，可放在 `01-美术/`。
- 聊天最终回复只给文档路径、摘要和下一步拍板问题，避免让用户手动整理。
- 不生成素材、不改代码的专项文档，也要写清“范围、禁止项、验收标准、制作人需要拍板的问题”。
