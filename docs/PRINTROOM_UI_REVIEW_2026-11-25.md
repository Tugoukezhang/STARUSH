## 检查规模和结论

- 在 Chromium 的 320×568、360×640、393×852、768×1024 和 1366×768 五档视口，逐页打开和关闭窗口，检验每个可操作控件的中心命中与热区大小。新号每档 262 项、五章通关档每档 311 项，总计 2,865 次。最短边约 44 CSS 像素，变换后有万分之一像素以内的浮点误差。
- 在 390×844 用 Firefox 与 Linux WebKit 各跑了一遍 21 页、40 窗与 262 项控件检查。两个引擎中“场地规则”行均为 44 像素，点行下缘可开合。最后一轮装备图面另在五档视口核对七张物品图和七张底图；320×568 用两种存档复测滚动和打开详情。另用正式网页模拟 390×844、三倍像素密度，确认七件实物、七张底图及书签详情均正常，卡名未溢出。
- 对同一新号逐一比较可见的 147 个一级按钮与折叠项，146 个的按钮表面、文字、子图或状态有可测变化；首页角色的透明互动区继续供玩家触摸立绘。可用与禁用项都算在这组外观比较内。上下页共用组件，数量不等同于独立原画张数。
- 五张 GPT 原稿切出十九幅运行图，另外两张是现有角色兵装的缩略图。合计二十一张、445,164 字节。构建收录 851 项资源，从正式网页重新读取这二十一张，比对文件内容、发布清单及 SHA-256 均一致。[原稿与复导方法](../01-美术/printroom/README.md)
- 正式构建从首页选择三位角色并进首章，实点释放技能、暂停、打开设置、关设置和继续。三名角色常规模式与两组减少动态模式共五次均走通，浏览器没有应用异常或 HTTP 失败。手机尺寸使用云端浏览器模拟；实体 iPhone Safari、低端机持续帧率与真机触感尚未实测。
- 同日发布、安可、暂停、摇杆关联行为、演出准备、名册动作等十个专项文件，65 项通过。另把内页旧用例改为从真实入口核对七件配件、三名角色、五个章节、预览不写档与旧版背包，6 项均通过。两组合计 71/71。发布和内页共五个原先失败的场景已在本轮跑通。上一轮全库清单保留其测量时间。[上轮全库检测记录](AI_AND_BUTTON_REVIEW_2026-11-25.md)

## 复核入口

在 `game/` 中运行 `npm run dev`，把实际端口填到 `STARUSH_QA_URL`。以下示例沿用 Vite 默认端口。脚本使用 Playwright，外置安装时可用 `STARUSH_PLAYWRIGHT_MODULE` 指向对应安装位置。

```sh
STARUSH_QA_URL=http://127.0.0.1:5173 node scripts/qa-menu-details.cjs
STARUSH_QA_URL=http://127.0.0.1:5173 STARUSH_QA_PROFILE=cleared node scripts/qa-menu-details.cjs
npm run build
```
