# 从首页走到后台的加载实测

在 390×844 的 Chromium 新窗口里，从正式构建的首页进背包，返回首页，进入巡演后台、成员休息室，再返回后台并进入场馆。每次重新开浏览器测冷启动，同一次试玩内保留正常缓存。全程监听浏览器实际收到的字节数，包括响应头。修前构建有 868 项发布资源，修后有 869 项。新增的一张小图是从首页原始标志裁下的可见部分。

## 首页的实际变化

| 测量项 | 修前 | 修后 |
| --- | ---: | ---: |
| 冷启动首页请求 | 28 次 | 25 次 |
| 冷启动首页实际传输 | 13,450,793 字节 | 3,832,977 字节 |
| 不限速七步合计传输 | 23,571,694 字节 | 9,014,477 字节 |
| 模拟慢网，首次出现首页布局 | 6.99 秒 | 7.56 秒 |
| 模拟慢网，首页请求完成并安静半秒 | 69.44 秒 | 21.97 秒 |

首页少传约 71.5%，七步路径少传约 61.8%。慢网使用 150 毫秒延迟、下载 200,000 字节/秒。每种条件各取一次，时间受同时运行的工作负载影响。「首次出现首页布局」表示能看到首页根节点。可点击性另做了实际操作，见下文。

## 调整和故障复验

- 首页原先为一个标志和设置键，分别请求约 3.55 MB 的两套横跨整页的透明元件图集。标志在屏幕上确有显示，现在只读 435×151 的原画裁切。裁切的透明通道与原稿一致，分别叠在黑底和白底时逐像素相同。设置已经有可见的线条图标，取消了会在渲染时被替换的旧图层请求。
- 首页的角色对话头像原来提前请求 2.46 MB 的红发原图；场馆排班另外请求约 4.94 MB 的绿发和蓝发原图。现在小头像复用 180 像素裁切。正式角色全身图的分辨率保持原样。
- 故意让标志与三张缩略头像返回 404，再打开首页角色对话和场馆排班。标志切回原 941×1672 图集中的同一局部，角色头像均成功解码为 1254 像素原图。正常路径实取了 435×151 标志与 180 像素小头像。两条路径都能显示角色对白及三人排班，应用无脚本异常。
- 另一次专门扣住新场景、纸框与小图的网络响应，画面加载期间实点首页、背包、返回、后台与场馆入口。检查了章名、开始按钮、背包物品、锁定文字和场馆条件在备用底色上的显示。该检查验证了素材未到位时仍能操作；网速表中的首屏时间没有计为第一次触摸延迟。

以上测量来自云端触屏视口。实体手机的无线网络、设备解码延迟和持续帧率需要另测。
