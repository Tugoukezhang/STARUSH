# 21 个页面和 42 个二级窗口的触屏复检

复检在 320×568 的演出档案抓到一个会点错地方的问题。工具区换行后，「章节现场档案」下移，与首章卡重叠。按钮本身高 44 CSS px，但点它中心 (160,191) 实际落在首章卡上。已将三个工具放回同一行，让列表从工具区下方开始。修后在同尺寸点这个按钮中心，实际进入「章节现场档案」。[320 像素修后实屏](device-archive-320.webp) · [档案布局](../../../game/src/styles/printroomInnerPages.css)

| --- | ---: | ---: | ---: | --- | ---: |

| Chromium 390×844 | 21 | 42 | 281 | 0 | 0 |

| Linux WebKit 390×844 | 21 | 42 | 281 | 0 | 0 |
| Chromium 320×568，修后五章通关档 | 21 | 42 | 324 | 0 | 0 |

五个新号样本共核 1,405 次。最窄档修复后，另用正式脚本和五章通关档重跑整轮，检查 324 个可操作控件，全部中心可命中，最短边 43.99997 CSS px。组内包含排练课题、配件筛选与成员切换的交互检查。各行均靠页面上真实可见的按钮打开窗口，然后测每枚可操作控件的宽、高和实际命中对象。可滚动内容先正常滚入视口，复选框按可点击标签测量。最短边以 44 CSS px 为标准，允许 0.02 px 的排版舍入。用路由定位到要检查的大页，禁用项不计入可操作控件数。这里复核的是浏览器中的触屏布局；没有用这些数字推断实体手机的 GPU 流畅度、震动、扬声器或触屏延迟。[可重复运行的窗口检查](../../../game/scripts/qa-menu-details.cjs) · [新号、通关档及实际玩法](product.md)
