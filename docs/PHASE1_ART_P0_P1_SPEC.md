# STARUSH Phase 1 P0/P1 美术规格升级

日期：2026-05-24
用途：供制作人评审、转发给美术专项、作为后续生成候选前的规格依据。
范围：只做规格和候选方向，不生成素材，不铺量。

## 总方向

Phase 1 美术不以数量验收，而以首玩 3 分钟、战斗可读性、原创识别和 Phaser 接入稳定性验收。

统一视觉方向：

- 高饱和偶像科幻舞台。
- 干净平涂。
- 2-3px 清晰线条。
- 竖屏弹幕可读性。
- 背景低亮度。
- 中央战斗区干净。

统一禁止项：

- 不使用具体商业游戏名作为提示词风格锚点。
- 不生成或仿制既有游戏的角色、UI、关卡、弹幕样式或文案。
- 不出现 logo、文字、广告牌。
- 不出现可识别角色。
- 不做满屏高亮灯点。
- 不做复杂花纹地板。
- 不贴近既有游戏关卡构图。
- 不做商店 UI、抽卡视觉、五人全套角色、敌人剪影升级。

## 通用 375x667 竖屏标准

- 背景平均亮度必须低于玩家、敌人、敌弹、我方弹幕。
- 中央约 180px 宽纵向战斗通道保持低细节、低对比。
- 底部玩家活动区约 160px 高不得有高频纹理或强光点。
- 顶部敌人出生区不得有高亮噪声、复杂线条或强图案。
- 高弹幕密度截图中，危险敌弹的识别优先级必须高于背景与命中特效。
- 50% 缩放截图中，玩家、敌人、敌弹、我方弹幕不能混成一团亮斑。

## P0-1 `stage-combat-idol-v1`

### 用途

第一战斗舞台背景。目标是让玩家一眼识别这是“偶像演出场”，同时不影响战斗读取。

### 升级规格

- 文件：`stage-combat-idol-v1.png`
- 尺寸：优先 `750x1334`，对应 `375x667` 的 2x；备选 `768x1024`。
- 格式：不透明 PNG。
- 画面：暗色舞台空间、顶部柔和聚光、抽象观众应援灯、中央纵向战斗通道干净。
- Phaser 接入：作为 BattleScene 最底层背景，`setDisplaySize(GAME_WIDTH, GAME_HEIGHT)`，现有舞台地板线、弹幕、敌人、C 位光效叠在其上。

### 原创候选方向

| 方向 | 视觉描述 | 可读性风险 | 相似性自查 |
|---|---|---|---|
| A 暗场聚光舞台 | 深蓝紫暗场，3-5 道柔和顶灯，中央留空。 | 过暗会吞角色轮廓。 | 检查舞台构图不贴近任何既有关卡截图。 |
| B 粉丝光海舞台 | 底部远景应援灯海，低亮度散点。 | 灯点过多会变成噪声。 | 灯海不能形成已有作品常见图案或标志。 |
| C 几何霓光剧场 | 抽象舞台弧线、低亮边缘光。 | 线条过亮会抢弹幕。 | 几何构图不模仿既有 UI 或舞台包装。 |
| D 小型首演舞台 | 更亲近的 Live 舞台，少量设备剪影。 | 设备轮廓太复杂会干扰底部。 | 不出现真实品牌设备、标牌、海报。 |

### 验收标准

- 手机尺寸下一眼能看出“偶像舞台/演出场”。
- 背景亮度低于玩家、敌人、敌弹、我方弹幕。
- 中央战斗通道和底部玩家区域干净。
- 不包含文字、logo、广告牌、可识别角色。
- 不贴近既有游戏关卡构图。

## P0-2 `bullet-color-atlas-v1`

### 用途

五色我方弹幕、五色拖尾、暴击星粒。目标是让玩家在 32x32 或更小显示下仍能区分颜色意义。

### 升级规格

- 文件：`bullet-color-atlas-v1.png` + `bullet-color-atlas-v1.json`
- 尺寸：`512x256` atlas。
- 格式：透明 PNG + JSON atlas。
- 单元：建议 `64x64`，实际显示约 `16-24px`。
- 帧数：约 16 帧。
- 帧命名：
  - `bullet_pink_0`
  - `bullet_blue_0`
  - `bullet_yellow_0`
  - `bullet_purple_0`
  - `bullet_orange_0`
  - `trail_pink_0`
  - `trail_blue_0`
  - `trail_yellow_0`
  - `trail_purple_0`
  - `trail_orange_0`
  - `crit_star_0..2`
  - `crit_spark_0..2`
- Phaser 接入：替换或补强当前 Graphics 弹幕绘制；拖尾接入玩家子弹 update 的 trail 生成逻辑。

### 原创候选方向

| 方向 | 视觉描述 | 可读性风险 | 相似性自查 |
|---|---|---|---|
| A 语义形状 | 粉心形、蓝水滴、黄星、紫菱形、橙火焰。 | 心形和星形太小会糊。 | 形状组合不能贴近既有彩色弹幕图案套装。 |
| B 应援光标 | 五色像演出灯标，轮廓更几何。 | 偶像感强，但可能不够“弹”。 | 不做成 UI 图标或按钮。 |
| C 音符能量 | 用音符弧线、节拍点做拖尾语言。 | 细线缩小后可能断。 | 不使用真实音乐软件或品牌符号。 |
| D 极简高读 | 大轮廓、少细节、外缘干净。 | 记忆点略弱。 | 确认不是通用素材库感。 |

### 32x32 缩小识别标准

- 五色不能只换色，必须靠颜色和轮廓双重区分。
- 灰度截图下至少 4 种轮廓仍可区分。
- 每帧外圈保留 4px 安全透明边。
- 弹体主体占 32x32 显示面积的 35%-60%。
- 拖尾长度克制，显示长度不超过约 48px。
- 拖尾透明度低于弹体，不遮挡敌弹。
- 暴击星粒必须和黄色普通弹区分：更尖、更短闪、更高亮，但范围更小。

### 验收标准

- 32x32 下五色可读。
- 拖尾不盖住敌弹。
- 边缘干净，无白边、黑边、脏像素。
- 高密度弹幕截图中，我方弹幕和敌弹不会混淆。

## P1-1 `impact-color-atlas-v1`

### 用途

普通命中和暴击命中特效。目标是让玩家知道“打中了、暴击了”，但不把命中特效误读成敌弹。

### 升级规格

- 文件：`impact-color-atlas-v1.png` + `impact-color-atlas-v1.json`
- 尺寸：`512x512` atlas。
- 格式：透明 PNG + JSON atlas。
- 单元：`64x64`。
- 帧数：40 帧。
- 结构：5 色 × 普通/暴击 × 4 帧。
- 帧命名：
  - `impact_pink_normal_0..3`
  - `impact_pink_crit_0..3`
  - 其他颜色同规则。
- 时长：普通命中 0.2-0.3s，暴击命中 0.3-0.45s。
- Phaser 接入：普通命中接 BattleScene 子弹命中敌人回调；暴击接暴击 FX 触发点；动画播放完成后 destroy。

### 原创候选方向

| 方向 | 视觉描述 | 可读性风险 | 相似性自查 |
|---|---|---|---|
| A 小型闪裂 | 中心点爆开，短线碎光。 | 线条太尖会像敌弹。 | 不复制既有命中火花轮廓。 |
| B 圆环脉冲 | 小圆环扩散后消失。 | 太圆可能像护盾或范围技能。 | 圆环比例不模仿常见 UI 特效。 |
| C 色块碎片 | 同色小碎片向外散。 | 碎片太多会遮敌人。 | 不做涂抹飞溅式既视感。 |
| D 暴击尖闪 | 普通小闪，暴击加星尖光。 | 暴击过亮会遮弱点。 | 星形不能和黄色普通弹混淆。 |

### 375x667 标准

- 普通命中特效最大可见范围不超过 48px。
- 暴击命中特效最大可见范围不超过 72px。
- 不覆盖玩家判定点。
- 不持续遮挡 Boss 弱点。
- 红/橙命中特效不能长得像敌弹。
- 高密度弹幕截图中，命中特效应低于敌弹危险识别优先级。

### 验收标准

- 普通命中和暴击命中一眼不同。
- 0.5 秒内读完。
- 不误判为敌弹。
- 颜色和弹体语义一致。

## P1-2 `support-moment-atlas-v1`

### 用途

安可、C 位、全五色合击，以及必要的 Support/Combo Break 符号反馈。目标是建立 STARUSH 的记忆点，但不靠大字刷屏。

### 升级规格

- 文件：`support-moment-atlas-v1.png` + `support-moment-atlas-v1.json`
- 尺寸：推荐 `1024x512` atlas。
- 格式：透明 PNG + JSON atlas。
- 单元：`128x128`。
- 帧数：约 24-28 帧。
- 帧命名：
  - `support_0..3`
  - `encore_0..5`
  - `center_stage_0..5`
  - `combo_break_0..3`
  - `rainbow_union_0..5`
- Phaser 接入：
  - Support/C 位接应援值满或 C 位开始回调。
  - Encore 接安可开始回调。
  - Combo Break 接 combo 断裂回调。
  - 全五色合击接全五色触发回调。

### 原创候选方向

| 方向 | 视觉描述 | 可读性风险 | 相似性自查 |
|---|---|---|---|
| A 舞台灯语义 | C 位是中心聚光，安可是观众返场光浪。 | 两者都用光，容易混。 | 形状来源不同：一个自上而下，一个自下而上。 |
| B 应援能量语义 | 安可是外圈回应，C 位是角色脚下焦点。 | 外圈过大会挡弹。 | 不做成现成音游 UI 结算感。 |
| C 五色汇聚语义 | 全五色从五方向汇入中心再爆发。 | 过亮会白成一团。 | 五色轨迹必须保留，不变成白闪。 |
| D 极简符号语义 | C 位用聚光框，安可用波纹，合击用五色环。 | 可能显得 UI 化。 | 不出现按钮、徽章、logo 感。 |

### 安可/C 位/全五色合击差异化标准

- 安可：来自“观众/场外回应”，视觉方向建议从底部或外圈向战场回应。
- C 位：来自“舞台中心/角色高光”，视觉中心必须围绕玩家或舞台中轴。
- 全五色合击：必须看到五色分别进入、汇聚、爆发三个阶段，不能只是白光一闪。
- Combo Break：低亮、碎裂、降温，不使用高奖励感视觉。
- Support：能量上升、应援积累，不和 Encore 的高潮返场混淆。

### 验收标准

- 安可和 C 位一眼不同。
- 全五色合击体现五色汇聚，不是白光一闪。
- 高潮出现时玩家能记住，但不影响躲弹。
- 不只靠文字表达。
- 不遮挡玩家、敌弹和关键命中反馈。

## 通用原创性自查清单

每个候选生成后必须逐项检查：

- 提示词、文件名、归档备注中不出现具体商业作品名。
- 不使用既有游戏截图作为直接构图参考。
- 不出现 logo、文字、广告牌、真实品牌、可识别角色。
- 背景不贴近既有游戏关卡构图。
- 弹幕不复制既有五色图案组合。
- 特效不复刻常见 UI、抽卡、商店、结算包装。
- 每个候选做 375x667、50% 缩放、高弹幕密度三种检查。
- 每个候选保存生成工具、日期、提示词、人工修改记录、用途、版权备注。

## 最终生成前需要制作人拍板的问题

1. 第一舞台方向选 A 暗场聚光、B 粉丝光海、C 几何霓光、D 小型首演中的哪 2-4 个先出候选？
2. 五色弹幕是否沿用“粉心、蓝水滴、黄星、紫菱、橙火”的语义，还是改成更抽象的应援光标？
3. C 位视觉中心是绑定玩家脚下，还是绑定屏幕中心舞台？
4. 安可视觉更偏“观众回应”还是“舞台返场灯光”？
5. 全五色合击是从玩家汇聚、从敌人汇聚，还是从屏幕五方向汇聚？
6. 背景最终尺寸拍板：`750x1334` 2x 适配，还是沿用现有 `768x1024`？
7. 第一轮每个资产出 2 个候选还是 4 个候选？建议 P0 各 4 个，P1 各 2 个。
